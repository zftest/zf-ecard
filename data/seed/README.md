# 种子词库填写说明

这个目录里放的是**源码级**数据，必须进 Git。数据库（`data/app.db`）和音频（`data/audio/`）是生成物，不入库。

| 文件 | 用途 | 能不能手改 |
|---|---|---|
| `units.pep.2024.grade7.csv` | 人教版 2024 版七年级上下册的单元骨架（20 个单元） | 可以，单元名以教材为准 |
| `words.sample.csv` | **已核验的 50 个词 / 52 个义项**，用于跑通开发链路 | 只读参考，别改 |
| `words.template.csv` | 空表头模板，复制成 `words.grade7.csv` 后往里填 | 复制后随便改 |

---

## 一、怎么开始填

```bash
# 1. 复制模板
copy data\seed\words.template.csv data\seed\words.grade7.csv

# 2. 用 Excel 或 VSCode 打开填写（Excel 直接双击，已带 BOM 不会乱码）

# 3. 空跑，只看不写库（强烈建议先跑这一步）
.\.venv\Scripts\python.exe tools\load_seed.py --words data\seed\words.grade7.csv --dry-run

# 4. 确认无误后正式导入
.\.venv\Scripts\python.exe tools\load_seed.py --words data\seed\words.grade7.csv
```

**为什么一定要先 `--dry-run`**：它会逐行报错并给出行号，但不动数据库。正式导入时如果有错，是导入到一半停下，你会得到一个半截状态。空跑可以先把格式问题全部清掉。

## 二、列的含义

### 必填（缺了这行直接失败）

| 列 | 说明 | 示例 |
|---|---|---|
| `unit_code` | 单元编号，必须能在 `units.pep.2024.grade7.csv` 里找到 | `SU01`、`U03` |
| `spelling` | 单词拼写，小写开头，专有名词照教材大小写 | `environment`、`Chinese` |
| `pos` | 词性，**带点** | `n.`、`v.`、`adj.`、`adv.`、`int.`、`prep.`、`pron.`、`conj.`、`num.` |
| `meaning_zh` | 标准中文释义，**这是判题的唯一标准答案** | `环境` |

### 可选，但强烈建议填

| 列 | 说明 | 不填的后果 |
|---|---|---|
| `phonetic_uk` | 英式音标，**带斜杠** | 「音标写词」题型出不了题 |
| `phonetic_us` | 美式音标 | 只能显示英音 |
| `theme` | 主题分类，用于「按主题练」 | 分类筛选中缺失 |
| `example_en` / `example_zh` | 例句 | 答错时没有例句可看 |
| `accepted` | **人工维护的同义写法**，多个用 `\|` 或 `/` 分隔 | 孩子写「自然环境」会被判错 |

### 溯源列（可以留空，填了更规范）

| 列 | 说明 |
|---|---|
| `source` | 来源标记，如 `PEP2024`、`ECDICT` |
| `source_license` | 许可说明 |
| `verify_status` | `pending` / `confirmed` —— 你自己核对过就改 `confirmed` |

## 三、四个最容易填错的地方

### 1. 一个词有多个意思 → 写多行，改 `sense_order`

这是本项目最重要的一个设计。**判题绑定的是「义项」，不是「单词」**。

```csv
U01,class,n.,/klɑːs/,,1,班级,班,学校,I'm in Class Two.,我在二班。,PEP2024,,confirmed
U01,class,n.,/klɑːs/,,2,课,课程,学校,We have four classes today.,我们今天有四节课。,PEP2024,,confirmed
```

两行的 `spelling` 和 `pos` 完全相同，只有 `sense_order` 不同（1 和 2）。

**为什么不能合成一行写「班级/课」**：那样错词本里 `class` 只有一条记录，孩子答错「课」这个意思，系统会以为他连「班级」也不会。分开记，才能做到「只练答错的那个意思」。

`sense_order` 不填默认是 1。**第一个义项会被当作「主释义」**，在其他题型（比如英译汉）里优先展示。

### 2. `accepted` 是给中文题用的，英文题不需要

```csv
U02,grandpa,n.,/ˈɡrænpɑː/,,1,爷爷,祖父|外公|姥爷,家庭,Grandpa likes reading.,爷爷喜欢看书。,PEP2024,,confirmed
```

孩子答「外公」，`爷爷` 是标准答案，命中 `accepted` 里的 `外公` → **判为正确**。

反过来，`spelling` 是英文题的标准答案，孩子把 `grandpa` 写成 `grandfather` 就是**错的**——因为那是另一个词，不是同义写法。

**这列是你手工维护的**（对应你选的 Q3 决策）。建议先只维护高频词，不要一次填完。填错了会放宽判题标准，比判严更危险。

### 3. 同一个词不要填进两个单元

数据库有全局唯一约束 `(spelling, pos)`。教材里 `school` 在 Starter Unit 3 和 Unit 3 都会出现，**只填首次出现的那个单元**，`unit_id` 记的就是首现单元。

如果填了两次，第二行会报 `失败` 并告诉你行号。跨单元复现留给后面的 `word_units` 关联表，现在不做。

### 4. 中文释义里不要带括号和词性标注

| 写法 | 结果 |
|---|---|
| `环境` | ✅ 正确 |
| `环境（名词）` | ❌ 孩子永远答不对 |
| `n. 环境` | ❌ 同上 |
| `环境 `（尾部空格） | ⚠️ 会被自动清理，但不建议依赖 |

判题前会做规范化（去空格、全角转半角、弯引号转直引号），但**括号和词性标注不会被去掉**，因为那可能是释义的一部分（如「（身体）健康的」）。

## 四、导入后怎么核实

```bash
# 看每个单元实际有多少词
.\.venv\Scripts\python.exe tools\load_seed.py --words data\seed\words.grade7.csv
```

输出末尾的「每个单元的实际词数」表就是设置页里「Unit 3 · 20 词」那个胶囊的真实来源。

**如果某个单元是 0**，说明这个词表还没覆盖到它，抽题时会抽空——这正是「胶囊写 20、实际 13」那个 bug 的防线：数字永远由数据算出来，不写死。

## 五、现在只有 50 个词，够用吗

够跑通开发，不够给孩子用。

- **20 个单元**已建好骨架（上册 Starter 1–3 + Unit 1–7，下册 Unit 1–8）
- **50 个词 / 52 个义项**已核验，集中在 SU01–SU03、U01、U02

剩下 15 个单元是 0 词。补齐方式二选一：

1. **照教材录**（推荐）——最准，且法律上最干净
2. **从 ECDICT 筛**（`https://github.com/skywind3000/ECDICT`，MIT 许可）——用 `zk` 标签过滤中考词，导出候选后**仍需你逐条确认**

我不会凭记忆批量生成词条。理由很直接：错一个词，孩子就背错一个，而且错得毫无痕迹——你只会以为是他记不住。
