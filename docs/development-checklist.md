## 0. 怎么用这份清单

- 按 **B1 → B8** 顺序执行，每个批次独立可验证、可提交、可回滚。
- 每批次做完停下来一起过，确认后再进下一批。
- 「影响源码」列区分：**是**=改动业务代码（需回归）；**新增**=只加文件不改旧代码；**否**=只动配置/文档。
- 「风险/回滚」列给出出错时怎么退。所有批次都以 `git` 提交为界，回滚命令统一是 `git revert <commit>`。

## 每批次完成后的固定动作

```bash
# 1. 先跑测试（必须全绿才提交）
run-tests.bat

# 2. 确认没有误加敏感文件
git status --short
git ls-files | grep -E '(^|/)config\.py$'    # 必须无输出

# 3. 提交 + 推送
git add -A
git commit -m "feat(模块): 说明"
git push origin main
```

> **必须从项目根目录运行测试。**
> pytest 只在「当前目录 == rootdir」时才应用 `pytest.ini` 里的 `testpaths`。
> 在 `.venv\Scripts` 下执行会打印 `no tests ran in 0.01s`，退出码 **5**（=未收集到测试），不是 0。
> 用 `run-tests.bat`（内部会 `cd /d "%~dp0"`）可以无视当前目录，且在退出码 5 时明确报错。
