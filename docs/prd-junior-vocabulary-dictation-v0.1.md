# 初中单词 3000 与分类默写产品规格说明书

| 文档项 | 内容 |
|---|---|
| 文档版本 | v0.1（讨论稿） |
| 日期 | 2026-11-02 |
| 所属项目 | 知识卡生成系统新增学习模块 |
| 产品代号 | 初中单词 3000 · 分类默写 |
| 目标终端 | 响应式 Web，优先桌面浏览器，兼容手机/平板 |
| 首版用户 | 单个初中生本地使用，兼顾家长查看结果 |
| 文档状态 | 待讨论词库来源、首版题型、发音方案与账号范围 |

> 本 PRD 只定义产品与接口草案，不代表相关功能已经开发。现有知识卡功能保持不变。

## 1. 一句话定位

**面向初中生的“教材同步词库 + 分类主动默写 + 错词复习”工具：不是让学生反复看单词，而是验证能否脱离提示正确写出，并针对错词持续复习。**

## 2. 背景与问题

现有项目支持小学/初中/高中知识卡生成，但英语模块主要是“内容展示”，没有形成学习闭环：

```text
当前：选择单元 → AI 生成知识卡 → 查看/下载海报
目标：选择词库 → 学习/默写 → 判分 → 错词归因 → 针对复习 → 查看掌握进度
```

需要解决的核心问题：

1. **再认不等于产出**：看到英文认识，不代表看到中文或听到发音能正确拼写。
2. **3000 词不能一次性灌输**：必须按教材、单元、主题、词性和难度组织成小任务。
3. **错题本容易只进不出**：错词必须自动生成下一次可执行的复习任务。
4. **结果反馈不能只给红叉**：要区分首答正确、提示后正确、答错和未作答。
5. **词库是内容工程**：词义、音标、发音、可接受拼写和分类质量，比页面数量更影响学习效果。

## 3. 产品目标与非目标

### 3.1 产品目标

| 目标 | 说明 |
|---|---|
| G1：可学 | 学生能按教材单元或主题找到明确的一组词，并获得音、形、义、例句输入 |
| G2：可写 | 学生能完成看中文写英文、听音写词等主动产出练习 |
| G3：可判 | 判分规则一致、可解释，大小写和标点等边界不产生误伤 |
| G4：可改 | 答错后能看答案差异，并一键进入“只练本次错词” |
| G5：可续 | 刷新或重启后仍能恢复练习与错词记录，不因代码更新清空数据 |
| G6：可衡量 | 用首答正确率、提示依赖、错词重练通过率等指标反映真实掌握情况 |

### 3.2 首版非目标

- 不做社交、班级排行榜、公开 PK。
- 不做复杂积分商城和过度游戏化。
- 不做教师班级管理、家长账号体系和云同步。
- 不做手写 OCR 批改。
- 不在 MVP 自研复杂 AI 遗忘算法。
- 不将 AI 自动生成的词义、音标直接作为未经审核的核心词库。
- 不为了技术先进而重写现有知识卡模块。

## 4. 用户与核心场景

### 4.1 用户角色

| 角色 | 诉求 | 首版支持方式 |
|---|---|---|
| 初中生 | 任务短、操作快、知道错在哪里、能针对性重练 | 完整支持 |
| 家长 | 看本次结果与薄弱词，不替孩子操作 | 查看结果页与错词列表 |
| 内容维护者 | 导入、校验和维护 3000 词及分类 | 提供导入规范与数据校验，暂不做复杂后台 |

### 4.2 核心场景

1. **课后单元过关**：选择“七年级上册 / 人教版 / Unit 1”→ 20 词 → 看中文写英文 → 错词重练。
2. **周末分类复习**：选择“校园生活”主题 → 随机 20 词 → 混合复习 → 查看薄弱分类。
3. **考前错词清理**：进入错词本 → 只选高频错词 → 听音写词 → 直到本轮通过。
4. **中断后继续**：练习中途刷新页面 → 恢复当前题与已提交结果 → 不重复计分。

## 5. 行业方案对标与取舍

### 5.1 机制对标

| 产品/方案 | 值得借鉴 | 本项目采用方式 | 不照搬的部分 |
|---|---|---|---|
| 百词斩 | 图像与多感官输入降低初次学习门槛 | 图片可作为后续辅助输入 | 不用“看图选对”直接判定会默写 |
| 不背单词 | 真实例句和语境帮助理解词义与搭配 | 词卡保留例句，P1 增加语境填词 | 不把首版做成厚重内容社区 |
| 墨墨背单词 / Anki | 按记忆状态安排复习，而不是固定重复全部词 | P1 先做可解释的间隔复习，保留每词记录 | MVP 不引入难验证的黑盒算法 |
| 扇贝单词 | 拼写、听写等主动输出验证掌握 | 默写是主流程，而非附属测试 | 不堆叠过多学习入口 |
| Quizlet | 学习集、随机顺序、多题型和快速练习 | 分类词表可快速组成练习集 | 不做公开学习集社区 |
| Vocabulary.com | 多种题型；提示会影响得分；错后复现与掌握后回访 | 区分首答/提示后答对；错词进入复习 | 不采用复杂积分体系 |
| Duolingo | 间隔重复与掌握度动态变化的产品理念 | 后续根据每词表现调整复习时间 | 不在缺少数据时宣称使用同等算法 |

### 5.2 对标后的产品原则

1. **输入与检测分开**：图片、词卡用于学习；默写用于验证。
2. **掌握度必须包含“写”**：只答对选择题，不得显示“已掌握拼写”。
3. **分类服务于任务**：默认教材单元，主题分类用于补充，不做多层复杂目录。
4. **反馈立即且具体**：展示用户答案、正确答案和差异位置，避免只有“错误”。
5. **少而有效**：默认每次 20 词，可切 10/20/30；不默认一次 100 词。
6. **掌握可以回退**：后续复习再次答错，应重新进入学习中/待复习。

## 7. 信息架构

### 7.1 一级导航

```text
知识卡（现有） | 单词学习 | 分类默写 | 错词本 | 学习记录
```

- **知识卡**：保留现有生成与下载能力。
- **单词学习**：浏览词库、查看词卡、选择学习范围。
- **分类默写**：配置并执行默写，是新增模块主入口。
- **错词本**：查看与重练，不只展示列表。
- **学习记录**：P1 展示趋势；MVP 仅保留本次结果和历史会话基础数据。

### 7.2 核心用户流程

```text
选择词库（初中 3000）
  → 选择分类（默认教材单元，可切主题）
  → 选择模式（看中文写英文 / 听音写词）
  → 设置题量与顺序（默认 20 / 随机）
  → 默写作答（提交 → 反馈 → 下一题）
  → 结果页（首答正确率 / 提示后答对 / 错词）
  → 只练错词 / 返回词库
```

### 7.3 异常流程

- 当前筛选无词：禁止开始，并提示调整分类。
- 音频失败：允许重试；可切换看中文写英文，不让练习卡死。
- 刷新/关闭后返回：恢复到最近未完成练习。
- 重复点击提交：同一题只记录一次。
- 中途退出：弹出轻量确认；保留进度。
- 词库缺失或损坏：显示内容错误提示，不进入空白练习。

## 8. 功能详细规格

### 8.1 F01 初中 3000 词内容工程

| 项目 | 规格 |
|---|---|
| 词库规模 | 产品目标约 3000 个有效词条；不是一次学习任务 |
| 内容分层 | 课标/教材核心词、教材同步词、拓展提升词；具体口径待词库来源确认 |
| 基础字段 | 单词、词性、中文释义、音标、例句、例句翻译、难度、来源 |
| 发音字段 | 音频 URL 或发音策略；至少一种可用英文发音 |
| 分类字段 | 教材、年级、册别、单元、主题、词性、难度 |
| 判分字段 | 标准答案、可接受答案列表、是否区分连字符等 |
| 版本字段 | 词库版本、来源、更新时间，便于追踪内容修订 |

**数据质量门禁：**

1. 每个词条有稳定唯一 ID，不能只以英文拼写作为数据库主键。
2. 英文词形、词性、中文释义不得为空。
3. 重复词、重复 ID、空音频、非法分类必须有导入报告。
4. 多义词需明确默写时展示哪个释义；不能把学生未写的另一个词义误判为错。
5. 英美拼写、缩写、连字符和撇号需配置可接受答案，不能靠临时宽松判分。
6. 词库来源与使用许可必须确认；未经授权不直接抓取商业产品词库。

### 8.2 F02～F04 词库浏览与学习卡

**筛选优先级：**

1. 默认：教材版本 → 年级 → 册别 → 单元。
2. 切换：主题分类 → 难度。
3. 辅助：词性、搜索关键词、是否错词。

**学习卡内容：**

- 英文单词、词性、中文释义。
- 音标与播放按钮。
- 一个简洁例句及翻译。
- 所属单元与主题标签。
- “加入本轮默写”或“开始本组默写”。

首版不要求每个词都配图，避免内容成本膨胀和图片依赖。

### 8.3 F06～F09 默写设置

| 设置项 | 控件建议 | 选项/默认值 |
|---|---|---|
| 练习模式 | 分段单选 | 看中文写英文（默认）/ 听音写词 |
| 题量 | 分段单选 | 10 / 20（默认）/ 30 |
| 出题顺序 | 单选 | 随机（默认）/ 词表顺序 |
| 提示 | 开关 | 默认关闭；开启后可主动查看首字母 |
| 反馈方式 | 单选 | 即时反馈（默认）；集中反馈可放 P1 |

**交互规则：**

- 分类支持多选时用复选框；模式、题量等互斥项用单选/分段控件，不混用语义。
- 开始按钮前显示“本次将练习 N 词”。
- 可选词不足设定题量时，按实际数量出题并明确提示。
- 随机出题需保证同一会话不重复。

### 8.4 默写作答页

页面元素从下到上保持单一任务焦点：

1. 顶部：当前进度 `6 / 20`、本次首答正确数、退出。
2. 题干：中文释义与词性，或音频播放按钮。
3. 输入：英文拼写输入框，自动聚焦。
4. 辅助：重听、首字母提示；提示使用必须被记录。
5. 操作：提交答案；提交后变为下一题。
6. 反馈：正确/错误图标与文字、用户答案、标准答案、差异提示。

**键盘规则：**

- `Enter` 提交；反馈展示后 `Enter` 进入下一题。
- 提交前按钮禁用空答案。
- 提交后禁用重复提交。
- 下一题出现后焦点回到输入框。
- 不依赖鼠标才能完成练习。

### 8.5 判分规则

判分必须“宽松处理无意义输入差异，严格处理真正拼写差异”。

| 规则 | 默认处理 | 示例 |
|---|---|---|
| 首尾空格 | 去除 | `␣apple␣` → `apple` |
| 连续空格 | 合并为一个 | `ice␣␣cream` → `ice cream` |
| 英文字母大小写 | 默认忽略 | `Apple` 与 `apple` 均可 |
| 中文/弯撇号 | 归一化为英文撇号 | `don’t` → `don't` |
| 连字符 | 默认保留并严格比较 | `ice-cream` 不自动等于 `ice cream` |
| 英美拼写 | 仅在词条配置为可接受答案时通过 | `color` / `colour` 需明确配置 |
| 多答案 | 任一审核通过的答案即正确 | 以词库 `accepted_answers` 为准 |
| 词形变化 | 未要求时不接受其他词形 | 目标 `go`，答 `went` 不通过 |
| 空答案 | 不允许提交 | 不计为答错，直到用户选择跳过 |
| 提示后答对 | 结果正确但单独标记 | 不计入“无提示首答正确” |
| 答错后修改 | 同一题只保留首答结果 | 防止反复试答刷高首答率 |

### 8.6 结果页与错词重练

结果页必须回答三个问题：**这次怎么样、错在哪里、下一步做什么。**

| 区域 | 内容 |
|---|---|
| 核心结果 | 实际题数、无提示首答正确数、首答正确率、提示后答对数 |
| 错词清单 | 用户答案、标准答案、中文释义、播放、错误差异 |
| 下一步 | 主按钮“只练本次错词”；次按钮“再练一组” |
| 分类反馈 | P1 展示薄弱主题/单元，不做无依据能力评分 |

错词重练通过后仍保留历史记录，不直接物理删除；可在视图中标记“本轮已通过”。

### 8.7 掌握与复习模型

#### MVP：可解释的状态模型

| 状态 | 进入条件 |
|---|---|
| 未学习 | 没有学习或作答记录 |
| 学习中 | 已看过词卡或参与过默写 |
| 待复习 | 曾答错、提示后答对，或到达复习时间 |
| 本轮通过 | 当前练习无提示首答正确 |
| 已掌握 | P1：跨不同日期多次无提示正确，并通过抽测 |

**单次答对只能叫“本轮通过”，不能立即叫“永久掌握”。**

#### P1 复习策略

- 初始可使用 1/3/7/15 天等固定可解释间隔。
- 答错降低掌握状态并缩短间隔；连续无提示答对逐步拉长。
- 每日复习量应有上限，优先高风险错词，避免错词越积越多。
- 后续有足够真实数据后，再评估个性化间隔模型，不在 MVP 伪称 AI 记忆算法。

## 9. UI 与体验规格

### 9.1 设计方向

- 风格：清爽、学习工具感、低干扰；沿用现有英语蓝色主题，但建立统一色彩变量。
- 布局：练习主卡最大宽度约 720px，桌面居中；手机端单列。
- 导航：学习/默写/错词入口清晰，练习中收起非必要操作。
- 动效：150～250ms 状态过渡；答错不使用剧烈抖动或羞辱性文案。
- 游戏化：只保留进度和完成反馈，不做强制连续打卡与排行榜。

### 9.2 关键状态

| 状态 | 必须有 |
|---|---|
| 默认 | 清晰题干、可聚焦输入框、明确主按钮 |
| 加载 | 播放或创建会话时有状态，不重复提交 |
| 正确 | 图标 + “回答正确”，不能只变绿色 |
| 错误 | 图标 + “需要订正”，答案差异可读，不能只变红色 |
| 提示后正确 | 与完全独立答对区分 |
| 音频失败 | 可重试，并可切换题型 |
| 空分类 | 说明原因并提供返回筛选 |
| 恢复会话 | 明确显示“已恢复上次练习” |

### 9.3 可访问性与响应式

- 文本和背景对比度满足基本可读性，焦点框清晰。
- 正误状态同时用文字/图标表达。
- 移动端输入框与按钮触控区域不小于约 44px。
- 手机端软键盘弹出时，题干和提交按钮不被遮挡。
- 音频按钮有文本替代与禁用状态。
- 为后续 UI 自动化在关键控件预留稳定 `data-testid`，不依赖动态样式类名。

## 10. 数据模型草案

| 实体 | 关键字段 | 说明 |
|---|---|---|
| `Word` | `id, lemma, pos, meaning_zh, phonetic_uk, phonetic_us, example, example_zh, audio_url, difficulty, source` | 单词主数据 |
| `WordAnswer` | `word_id, answer, locale, is_primary` | 标准与可接受答案 |
| `Category` | `id, type, name, parent_id, sort_order` | 教材/单元/主题/词性等分类 |
| `WordCategory` | `word_id, category_id` | 单词与分类多对多关系 |
| `Wordbook` | `id, name, stage, version, source, status` | 如“初中 3000”词库及版本 |
| `PracticeSession` | `id, mode, filters_snapshot, size, order, status, started_at, finished_at` | 一次练习；保存筛选快照 |
| `PracticeItem` | `id, session_id, word_id, sequence, prompt_snapshot` | 会话题目，避免词库更新改变历史题 |
| `PracticeAnswer` | `id, item_id, answer_raw, answer_normalized, result, hint_used, duration_ms, client_attempt_id, created_at` | 作答记录与幂等标识 |
| `WordProgress` | `word_id, status, correct_count, wrong_count, hint_count, streak, last_practiced_at, due_at` | 单用户每词进度 |
| `WrongWord` | 可由作答与进度派生，或建视图 | 不建议只做一张无限堆积的静态表 |

首版为本地单用户，可不建立复杂账号体系；但数据表仍应避免把用户标识写死，便于以后扩展。

| 接口名 | 方法 | 地址 | 用途 |

### 11.3 新接口通用约束

- 会话创建后保存题目快照，前端不能通过修改请求任意替换答案。
- 当前题响应不下发标准答案；判分在服务端完成。
- `client_attempt_id` 用于防止网络重试造成重复作答。
- 所有错误使用统一结构，不再直接返回内部异常。
- 单词列表必须分页，3000 词不一次性无分页塞给页面。
- 旧 `/api/generate` 保持兼容；新契约只约束新增接口。

## 12. 非功能要求

| 维度 | 要求 |
|---|---|
| 数据持久化 | 练习、错词与进度落库；重启服务、刷新页面、代码更新均不得主动清空 |
| 性能 | 普通判分为本地规则处理，目标服务端处理低于 100ms；词库查询分页 |
| 可用性 | 音频失败不影响其他题型；单个词数据异常有明确错误，不拖垮整个词库 |
| 安全 | 新接口不返回密钥或内部异常；未来公网部署需鉴权与限流 |
| 隐私 | 首版本地单用户，不采集不必要的个人信息 |
| 可维护性 | 词库版本化；判分函数独立；会话与作答记录可追溯 |
| 可测试性 | 分类、判分、会话状态、进度更新均可做接口与单元测试 |
| 兼容性 | 首版覆盖主流桌面 Chrome/Edge；移动端做响应式验证 |

## 13. 指标体系（只保留能指导学习与产品的指标）

| 指标 | 定义 | 用途 |
|---|---|---|
| 无提示首答正确率 | 无提示且首次提交正确的题数 / 实际作答题数 | 衡量独立拼写能力 |
| 提示依赖率 | 使用提示的题数 / 实际作答题数 | 识别是否依赖答案线索 |
| 错词重练通过率 | 错词重练中无提示首答通过数 / 重练题数 | 判断订正是否有效 |
| 会话完成率 | 完成会话数 / 已开始会话数 | 定位题量或交互是否造成中断 |
| 待复习词数 | 当前需复习且未完成的词数 | 控制复习负担 |
| 掌握词数 | 满足跨日期复核条件的词数 | P1 核心学习结果指标 |

不把“学习时长、点击次数、打卡天数”单独当作学习效果；MVP 不设无依据的提分承诺。

## 14. 验收标准与测试重点

### 14.1 MVP 业务验收

1. 能导入并校验约 3000 词，错误数据有报告，成功数据可查询。
2. 能按教材单元和至少一种主题分类筛选并创建练习。
3. 看中文写英文完整走完“配置—作答—判分—结果—错词重练”。
4. 听音写词在音频正常与失败两种情况下都有可用路径。
5. 大小写、空格、撇号、连字符、多答案符合判分规则。
6. 使用提示后答对不会计入无提示首答正确。
7. 同题重复提交不会重复计数或推进两题。
8. 刷新页面后可恢复未完成练习，已完成记录不丢失。
9. 错词重练有独立结果，历史作答不被覆盖。
10. 现有知识卡生成、预览和导出功能不受影响。

### 14.2 QA 边界用例

- 筛选结果为 0、1、少于设定题量、恰好等于题量。
- 3000 词中存在重复拼写但不同词性/词义的词条。
- 音频 404、超时、自动播放被浏览器拦截。
- 快速双击 Enter、网络重试、重复 `client_attempt_id`。
- 练习中途修改词库，历史会话题目快照仍一致。
- 词库更新后 ID 稳定，历史进度不会串词。
- 空答案、纯空格、超长输入、Unicode 撇号、连字符和大小写组合。
- 中途退出、刷新、浏览器重启与服务重启后的恢复。
- 结果页分母使用实际作答题数，跳题和未完成状态不混淆。
- UI 自动化使用稳定选择器，覆盖开始、作答、判分、错词重练主链路。

## 15. 分阶段实施建议

| 阶段 | 范围 | 出口标准 |
|---|---|---|
| M0：内容与技术验证 | 确认词库来源；抽样审核；确定发音；完成判分规则与接口契约 | 词库样例通过评审，核心规则无歧义 |
| M1：默写 MVP | 词库筛选、学习卡、看中文写英文、听音写词、结果、错词、持久化 | 主链路与边界用例通过，旧功能无回归 |
| M2：复习与反馈 | 学习记录、固定间隔复习、分类薄弱项、打印默写单 | 错词能按风险复习，报告能指导下一次练习 |
| M3：能力拓展 | 语境填词、词形转换、错因标签、个性化调度评估 | 新能力有明确学习价值，不靠功能数量堆砌 |

## 16. 四角色评审结论

### 16.1 资深产品视角（PM）

- 核心价值不是“有 3000 词”，而是**每次都知道练什么、写得对不对、接下来复习什么**。
- MVP 应收敛为“教材单元 + 看中文写英文/听音写词 + 错词重练”，暂不做账号、社区和复杂 AI。
- 词库来源与质量是启动前置条件；没有可靠词库，页面完成也不是可交付产品。
- 产品差异点是“分类默写闭环”，不是再做一个通用单词卡展示页。

### 16.2 资深 UI 设计视角（UI）

- 主界面只保留一个主任务，练习中避免知识卡、词库管理等入口争夺注意力。
- 分类多选、模式单选、题量单选使用正确控件语义。
- 正误反馈必须可访问、可解释，答案差异比红叉更重要。
- 输入焦点、Enter 流转、移动端键盘遮挡和音频失败是体验验收重点。
- 视觉先沿用现有英语蓝色，不必为首版重新设计完整品牌。

### 16.3 资深测试视角（QA）

- 判分规则是会引发最多争议的高风险点，必须先冻结规则再开发。
- “提示后答对”和“无提示首答正确”必须从数据层分开，否则报告失真。
- 会话快照、幂等提交、刷新恢复、词库版本是四个核心回归区域。
- 词库需要独立质量门禁；不能用随机抽样代替重复 ID、空释义等自动校验。
- 新功能上线必须带旧知识卡接口和页面回归。

### 16.4 资深开发视角（Dev）

- 推荐保留 Flask，新增独立模块/Blueprint 与 `/api/v1`，避免影响现有路由。
- 3000 词及学习记录建议使用 SQLite 起步，词库文件入库，不依赖手写 JSON 拼文件。
- 判分、抽题、会话状态、进度更新分别解耦，避免全部堆进 `app.py`。
- 采用 API 优先而非立即全站 Vue 化；MVP 验证后再决定独立前端工程，成本更可控。
- 发音优先复用合法音频或明确降级策略；不要在未验证浏览器语音效果前承诺统一发音体验。

## 17. 待讨论决策

| 决策 | 推荐方案 | 备选/影响 |
|---|---|---|
| D1：3000 词来源 | 使用有明确来源与许可的词库，先抽样审核再全量导入 | 若教材版本过多，首版仅支持一个版本 |
| D2：首版分类主线 | 默认教材单元，主题分类作为第二维度 | 纯主题分类会削弱课后同步价值 |
| D3：MVP 题型 | 看中文写英文 + 听音写词 | 若音频未就绪，先交付前者，但入口需标注降级 |
| D4：用户与数据 | 本地单用户 + SQLite 持久化 | 云账号会增加鉴权、隐私与同步成本 |
| D5：前端方案 | API 优先，先响应式 Web，验证后再独立 Vue3 | 立即全站分离会增加重构范围，但不改变产品目标 |
| D6：提示计分 | 提示后答对单独统计，不计入无提示首答正确 | 直接判错会打击使用提示，完全等同又会失真 |
| D7：打印功能 | 放 P1，与错词复习一起交付 | 若家长纸质默写是强需求，可提前到 M1 后首个迭代 |
