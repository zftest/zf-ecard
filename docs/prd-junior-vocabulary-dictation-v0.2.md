## 0. 版本记录与本轮结论

| 版本 | 主要变化 |
|---|---|
| v0.1 | 初版定位、分类默写 MVP、错词闭环、基础数据与接口草案 |
| v0.2 | 明确新旧架构共存；增加词源和 PDF 导入；补全读写、音标、汉英互译等题型；补齐全页面、子功能、状态与响应式 UI 规格 |

本轮形成四个明确结论：

1. **技术可行**：现有 Flask + Jinja2 知识卡系统保持原样；新功能使用 Vue3 独立前端与 Flask `/api/v1`，不需要拆成微服务。
2. **PDF 支持分级交付**：文本型 PDF 可先支持；扫描 PDF 需要 OCR；所有自动解析结果必须人工校对后发布。
3. **题型不等于同一能力**：认词、拼写、听写、发音和音标识别分别记录，不混成一个“掌握率”。
4. **AI 有明确边界**：AI 可辅助 PDF 结构化、例句、助记和错因解释；英文拼写正误由确定性规则判定，不由大模型随意判断。

## 1. 一句话定位

**面向初中生的“多来源词库 + 音形义学习 + 分类主动默写 + 错词复习”工具：不仅让学生见过单词，更能验证其是否会认、会写、会听、会读，并针对薄弱项继续练习。**

## 2. 背景与问题

现有项目支持小学/初中/高中知识卡生成，但英语模块主要停留在内容展示：

```text
当前：选择单元 → AI 生成知识卡 → 查看/下载海报
目标：建设词库 → 音形义学习 → 多模式默写 → 判分反馈 → 错词复习 → 分项掌握进度
```

需要解决的核心问题：

1. **再认不等于产出**：看到英文认识，不代表能根据中文、发音或音标正确写出。
2. **3000 词不能一次灌输**：必须按教材、单元、主题、词性、难度和学习状态组织。
3. **多词义不能混练**：同一英文词形可能对应多个词性、词义和读音，练习对象应明确到词义/词形单元。
4. **PDF 不是结构化词库**：版式、双栏、表格、扫描图像都会造成错行、漏词和错误配对。
5. **错题本不能只进不出**：错词必须生成下一次可执行的复习任务。
6. **AI 不能成为事实源**：词义、音标、发音和判分需要可追溯数据与明确规则。
7. **新旧系统要隔离演进**：新增前后端分离不能破坏旧知识卡生成、预览和导出。

## 3. 产品目标与非目标

### 3.1 产品目标

| 目标 | 说明 |
|---|---|
| G1：可建库 | 支持内置词库、结构化文件导入和分级 PDF 解析，来源与版本可追溯 |
| G2：可学 | 学生能获得词形、词性、释义、音标、发音、例句和拼写提示 |
| G3：可练 | 支持汉译英、英译汉、听音写词、音标写词、读写等递进方式 |
| G4：可判 | 判分规则一致、可解释，大小写、标点、多答案等边界不产生误伤 |
| G5：可改 | 答错后能看到答案差异、释义与发音，并一键进入错词重练 |
| G6：可续 | 刷新、重启、词库更新后仍能恢复练习和历史数据，不主动清空 |
| G7：可衡量 | 分别衡量认词、拼写、听写和发音，不制造单一虚假掌握率 |
| G8：可共存 | 新模块前后端分离，旧知识卡功能与路由保持兼容 |

### 3.2 首版非目标

- 不做社交、班级排行榜、公开 PK、积分商城。
- 不做教师班级管理、复杂家长账号和云同步。
- 不做手写 OCR 批改；PDF OCR 与手写作业批改是两个不同能力。
- 不在 MVP 自研黑盒 AI 遗忘算法。
- 不把 AI 生成的词义、音标直接发布为未经审核的核心词库。
- 不在没有合法音频与评测模型时承诺专业口语评分。
- 不重写旧知识卡系统，不将其强行迁移到 Vue。

## 4. 用户与核心场景

### 4.1 用户角色

| 角色 | 核心诉求 | 产品支持 |
|---|---|---|
| 初中生 | 任务短、操作快、知道错在哪里、能针对性重练 | 学习、默写、复习完整链路 |
| 家长 | 导入资料、查看结果与薄弱词，不替孩子作答 | PDF/文件导入、结果、错词和打印 |
| 内容维护者 | 建设可追溯词库，处理解析错误和重复词条 | 导入中心、校对、冲突处理、发布与版本记录 |

本地单用户版本可用角色视图区分“学习区”和“词库管理”，不必立即建设完整权限系统。

### 4.2 核心场景

1. **课后单元过关**：七年级上册 / 人教版 / Unit 1 → 20 词 → 汉译英 → 错词重练。
2. **周末分类复习**：选择“校园生活”主题 → 随机 20 词 → 英译汉 + 汉译英混合 → 查看薄弱项。
3. **听力拼写**：播放英文发音 → 输入拼写 → 重听 → 对照音标和词义。
4. **音标强化**：学习卡查看英美音标 → 听音 → 看音标写单词。
5. **纸质资料转词库**：上传文本型 PDF → 自动提取 → 人工校对 → 去重 → 发布为自定义词库。
6. **考前错词清理**：错词本筛选高频错词 → 听音写词 → 本轮通过 → 到期再次复习。
7. **中断后继续**：刷新或重启 → 恢复当前题和已提交结果 → 不重复计分。

## 5. 行业方案与 AI 背词设计对标

### 5.1 主流产品机制

| 产品/方案 | 值得借鉴 | 本项目采用方式 | 不照搬的部分 |
|---|---|---|---|
| 百词斩 | 图像、多感官输入、拼写与听读训练组合 | 图片作为辅助输入，拼写与听写作为检测 | 不用看图选对直接判定会默写 |
| 不背单词 | 真实语境、搭配和例句帮助理解 | 学习卡保留例句，后续增加语境填词 | 不做厚重内容社区 |
| 墨墨背单词 / Anki | 按记忆状态安排复习 | 先采用可解释间隔，再评估 FSRS 等算法 | 不在缺少数据时宣称同等效果 |
| 扇贝单词 | 拼写、听写、复述、纸笔式练习 | 默写作为主流程，保留打印默写单 | 不堆叠无关入口 |
| Quizlet | 学习集、随机顺序、Write/Spell 等题型 | 自定义词库快速组成练习集 | 不做公开学习集社区 |
| Vocabulary.com | 提示影响结果、错后复现、掌握后回访 | 区分首答/提示后答对，错词进入复习 | 不采用复杂积分体系 |
| Duolingo | 发音、拼写、间隔重复与动态掌握理念 | 分技能记录，后续按表现调整复习 | 不把多个能力压成一个分数 |

### 5.2 AI 记单词产品的可用能力与边界

| AI 能力 | 产品价值 | 本项目策略 | 风险控制 |
|---|---|---|---|
| PDF/图片结构化 | 降低资料录入成本 | AI 只辅助字段识别和纠错建议 | 必须显示置信度、原文页码并人工确认 |
| 个性化复习 | 减少无效重复 | 先用规则间隔，数据充分后评估个性化模型 | 不使用不可解释分数制造焦虑 |
| 生成例句/语境 | 增强理解与迁移 | P1 可选生成，标明 AI 辅助 | 词义与例句需校验，不修改原始事实字段 |
| 助记/联想 | 降低难词记忆负担 | P1 按错词按需生成 | 避免伪词源、错误词根和过度娱乐化 |
| 错因解释 | 帮助学生理解拼写差异 | 先规则标注，再由 AI 生成可读解释 | 不让 AI 改变确定性的正误结果 |
| 发音评测 | 发现读音问题 | P2 独立能力 | 不用浏览器 TTS 反向充当发音评分器 |
| 自由中文释义判分 | 处理同义表达 | 默认使用审核答案库，AI 仅提供“待确认建议” | 同义词误判时不直接影响历史成绩 |
| AI 对话陪练 | 增强语境运用 | P2 以后评估 | 不作为 MVP 核心，不替代词库与默写闭环 |

### 5.3 对标后的产品原则

1. **输入与检测分开**：图片、词卡、助记用于学习；默写用于验证。
2. **认、写、听、读、音标分项记录**：任一题型正确不能代表其他能力掌握。
3. **分类服务于任务**：默认教材单元，主题和自定义词库为补充。
4. **反馈具体可执行**：答案差异、音标、发音、释义与错词重练连成一个动作链。
5. **AI 辅助而不替代规则**：内容有来源，判分有规则，生成有标识。
6. **少而有效**：默认每次 20 词，不默认一次 100 词。

## 6. 新旧功能混合技术架构

### 6.1 可行性结论

**完全可行，推荐“旧系统原样运行 + 同仓库新增独立 SPA + 新 API 模块”的渐进架构。**

前后端分离指前端通过明确 API 契约获取数据，不等于必须再部署一套后端语言或微服务。现有 Flask 可以继续承担旧页面和新 API，两者互不强耦合。

### 6.2 技术路线比较

| 路线 | 做法 | 优点 | 代价/风险 | 结论 |
|---|---|---|---|---|
| A：Flask 新 API + Vue3 SPA | 旧页面不动，新增 Blueprint 和 `frontend/` | 改动小、部署简单、契约清晰、可独立回滚 | 需要一次性注册新入口 | **推荐** |
| B：新增 FastAPI + Vue3 | 新功能独立后端服务 | 服务边界更彻底 | 新增技术栈、端口、部署与运维成本 | 暂不需要 |
| C：全部迁移到新框架 | 旧知识卡也重写 | 技术统一 | 回归范围大、违背保留旧架构要求 | 排除 |

### 6.3 目标目录与运行结构

```text
knowledge-card-generato-main/
├─ app.py                       # 旧入口；只做新模块注册，不改旧业务逻辑
├─ templates/                   # 旧 Jinja 页面，保持
├─ static/                      # 旧静态资源，保持
├─ services/                    # 旧 DeepSeek / 海报导出，保持
├─ output/                      # 旧文件缓存与海报，保持
├─ new_backend/                 # 新增后端模块
│  ├─ api/                      # /api/v1 Blueprint
│  ├─ models/                   # SQLite / SQLAlchemy 模型
│  ├─ services/                 # 词库、判分、练习、导入、复习
│  └─ migrations/               # 数据库迁移，不靠启动时清空重建
├─ frontend/                    # 新增 Vue3 + Vite 独立前端
│  ├─ src/api/                  # 唯一后端访问层
│  ├─ src/router/               # /app 下新页面路由
│  ├─ src/stores/               # Pinia 会话与设置状态
│  ├─ src/views/                # 页面
│  ├─ src/components/           # 通用与题型组件
│  └─ package.json
└─ data/                        # 新数据库、私有导入文件；纳入持久化与备份
```

### 6.4 路由边界

| 路由 | 归属 | 是否改变 |
|---|---|---|
| `/` | 旧知识卡首页 | 不变 |
| `/generate`、`/api/generate` | 旧知识卡生成 | 不变 |
| `/poster/*`、`/poster-demo/*` | 旧海报预览 | 不变 |
| `/api/export/*`、`/loading` | 旧导出与等待页 | 不变 |
| `/api/v1/*` | 新功能 JSON API | 新增 |
| `/app`、`/app/*` | 新 Vue SPA | 新增 |

`/app/*` 的前端 history fallback 必须限定在 `/app` 前缀，不能使用全局 catch-all 覆盖旧海报路由。

### 6.5 开发与部署

**开发环境：**

- 旧 Flask 与新 API 仍运行在 `127.0.0.1:5000`。
- Vue Vite 运行在 `127.0.0.1:5173`。
- Vite 将 `/api/v1` 代理到 `5000`，前端只写相对路径 `/api/v1`。
- 通过代理同源访问时无需放开 CORS；若跨域直连，仅允许明确的开发来源。

**生产环境：**

1. `npm run build` 生成 `frontend/dist`。
2. Flask 在 `/app` 提供新 SPA 静态文件，在 `/app/assets` 提供构建资源。
3. 新 API 与 SPA 同域部署，无需跨域。
4. 原 Gunicorn `app:app` 方式可继续沿用，只需包含新增蓝图和静态入口。
5. 新前端或新 API 出问题时，可独立下线 `/app` 与 `/api/v1`，旧知识卡仍可用。

### 6.6 数据与依赖隔离

- 旧 `output/cache/*.json` 不迁移、不改格式。
- 新词库、练习和进度使用独立 SQLite 数据库。
- 新数据库变更必须通过迁移脚本，不在启动时删除重建。
- 新 Python 依赖只服务新模块，旧生成链路不改调用方式。
- 新前端构建失败不影响旧 Jinja 页面访问。
- 上传 PDF 存在私有数据目录，不放在公开静态目录。

### 6.7 技术验收底线

1. 旧知识卡首页、生成、预览、导出回归通过。
2. 新 SPA 刷新 `/app/words` 等子路由不出现 404。
3. 新前端不读取服务器文件或直接访问 SQLite，只通过 API。
4. 新 API 不向旧缓存目录写入学习数据。
5. 新旧静态资源路径不冲突。
6. 新功能可独立构建、测试和回滚。

## 8. 单词来源、导入与内容工程

### 8.1 词源优先级

| 来源 | 用途 | 优先级 | 规则 |
|---|---|---|---|
| 有明确许可的开放词库 | 建立基础词形、释义、音标 | 首选 | 保存来源、许可、版本和修订记录 |
| 合法教材配套词表 | 教材单元同步 | 首选 | 首版只选一个教材版本，避免范围失控 |
| 用户自有 CSV/JSON | 自定义学习集 | P0 | 模板校验、预览、去重后发布 |
| 用户自有文本 PDF | 资料数字化 | P1 | 自动提取草稿，人工校对后发布 |
| 扫描 PDF/图片 | 扫描资料数字化 | P2 | OCR + 置信度 + 原文对照 |
| AI 生成 | 例句、助记、解析辅助 | 受限 | 不作为未经审核的词义/音标事实源 |
| 商业背词产品词库 | 不作为直接来源 | 禁止未经授权抓取 | 尊重版权、许可和数据安全 |

### 8.2 “初中 3000”的内容口径

“3000”是词库产品规模，不是一次学习任务，也不等于 3000 条无结构英文单词。建议拆成：

1. **教材核心层**：当前教材要求掌握的词形、词性和核心词义。
2. **中考运用层**：常见搭配、熟词僻义和高频语境。
3. **拓展提升层**：主题拓展词，用于学有余力，不与核心掌握混算。
4. **自定义层**：家长或学生从 PDF、CSV 导入的个人词表。

每个词条必须标记层级、来源和适用教材，不把不同口径拼成一个无法解释的总数。

### 8.3 词库字段

| 字段组 | 字段 |
|---|---|
| 基础 | 稳定 ID、英文词形、词性、中文释义、词义序号、难度、层级 |
| 发音 | 英/美音标、英/美音频、发音来源、音频状态 |
| 学习 | 例句、例句翻译、常见搭配、可选图片、可选助记 |
| 判分 | 标准答案、可接受英文答案、可接受中文释义、连字符/大小写规则 |
| 分类 | 教材、年级、册别、单元、主题、词性、自定义词库 |
| 溯源 | 来源文件、页码、许可、词库版本、创建/修订时间 |
| 质量 | 校验状态、解析置信度、审核人/审核状态 |

### 8.4 数据质量门禁

1. 使用稳定唯一 ID，不能只以英文拼写作为主键。
2. 多词义/多词性按学习单元拆分，练习和进度关联到对应词义单元。
3. 英文词形、词性、中文释义不得为空；音标/音频缺失必须有状态而非假数据。
4. 重复词、重复 ID、非法分类、错误配对、空音频必须有导入报告。
5. 英美拼写、缩写、连字符、撇号需配置可接受答案。
6. 任何自动解析词条默认是“草稿”，不能直接出现在学生正式默写中。
7. 发布词库需要记录版本；历史练习保存题目快照，避免内容更新改写历史。

### 8.5 CSV/JSON 导入

**流程：** 下载模板 → 上传 → 字段映射 → 数据预览 → 校验 → 冲突处理 → 发布。

- CSV 必须明确 UTF-8 编码，提供可下载模板。
- JSON 必须带 `schema_version`，便于后续升级。
- 预览至少展示成功、警告、失败数量与逐行错误。
- 冲突处理支持保留现有、保留导入、人工合并；禁止默认覆盖。
- 导入发布是独立动作，上传成功不等于进入正式词库。

### 8.6 PDF 导入：是否支持

**支持，但不承诺“一键无错”。PDF 解析应定位为“生成可校对的词库草稿”。**

| PDF 类型 | 支持方式 | 阶段 | 主要风险 |
|---|---|---|---|
| 单栏文本型 | 文本提取 + 规则分行 + 字段识别 | P1 | 连字符换行、词义跨行 |
| 双栏/多栏文本型 | 按坐标识别栏位和阅读顺序 | P1 | 左右栏串行、表头误识别 |
| 表格词表 | 表格提取 + 列映射 | P1 | 合并单元格、跨页表格 |
| 扫描图片 PDF | OCR + 版面分析 + 字段识别 | P2 | 错字、音标乱码、低分辨率 |
| 复杂图文/手写 | 不保证自动解析 | 暂不支持自动发布 | 需要人工录入或专用处理 |

**标准流程：**

```text
上传 PDF
  → 安全与类型检查
  → 判断文本型/扫描型
  → 提取页面、栏位、表格和原始文本
  → 识别“单词 / 词性 / 释义 / 音标 / 单元”等候选字段
  → 规范化与置信度计算
  → 人工逐条/批量校对
  → 重复与冲突处理
  → 发布为词库草稿或正式版本
```

**技术选型建议：**

- 文本与坐标：PyMuPDF 优先；复杂表格用 pdfplumber 补充。
- 扫描 OCR：P2 评估 PaddleOCR，音标区域需要专项准确率验证。
- AI：只用于不固定版式的字段归并和纠错建议，输出必须带原文依据。
- 大文件解析走异步任务，不能阻塞 Flask Web 请求。

**建议限制（开发前可调整）：** 单文件 ≤20MB、≤200 页；仅允许 PDF；密码加密文件先提示用户解密；失败可重试并保留错误页码。

**PDF 质量验收：**

1. 每条候选词保留来源页码与原始文本。
2. 低置信度、跨行、缺失释义、疑似错行必须高亮。
3. 支持只看异常、批量确认、单条编辑和重新解析。
4. 音标、连字符、撇号、大小写、词性缩写纳入专项样本。
5. 扫描 PDF 未达到验收样本准确率前，不开放“自动发布”。
6. 原文件和草稿可删除，但删除操作必须由用户明确确认，不影响已发布词库。

## 9. 学习、读写、音标与默写方式

### 9.1 推荐学习闭环

```text
词义理解 → 音标/发音 → 例句语境 → 跟读/朗读 → 提示拼写 → 独立默写 → 错词复习
```

不是每次学习都必须走完全部步骤。学生可从词卡直接进入某一题型，系统按题型记录相应能力。

### 9.2 音标与发音设计

- 学习卡显示英文词形、词性、英/美音标和播放按钮。
- 音标使用统一字体与字符集，禁止用相似拉丁字符替代音标符号。
- 无音频时明确显示“暂无音频”，不能播放错误词或自动用不相干发音替代。
- 浏览器 TTS 只能作为降级方案，并标注“设备语音”；不作为标准英式/美式发音承诺。
- 播放次数、重听和提示使用可记录，但不直接等于学习能力评分。
- 看英文写音标涉及多读音和符号归一化，放 P2，不与看音标写英文混在一起。

### 9.3 全题型矩阵

| 模式 | 题干 → 学生作答 | 主要能力 | 判分方式 | 阶段 |
|---|---|---|---|---|
| 汉译英 | 中文释义 + 词性 → 英文拼写 | 拼写产出 | 确定性英文规则 | P0 |
| 听音写词 | 英文发音 → 英文拼写 | 音形对应 | 确定性英文规则 | P0 |
| 英译汉 | 英文词形 + 词性 → 中文核心释义 | 词义回忆 | 审核释义库；AI 仅建议 | P1 |
| 看音标写英文 | 音标 + 词性 → 英文拼写 | 音标与拼写映射 | 确定性英文规则 | P1 |
| 单词读写 | 听音/跟读 → 隐藏词形 → 拼写 | 阅读、发音与拼写联动 | 拼写规则；朗读另行记录 | P1 |
| 首字母提示默写 | 中文/发音 + 首字母 → 完整拼写 | 降低提取难度 | 正确但标记提示 | P1 |
| 字母填空 | 部分字母缺失 → 完整单词 | 拼写识别 | 逐空/整词规则 | P1 |
| 语境填词 | 英文例句空出目标词 → 拼写 | 语境运用 | 词形与可接受答案 | P1 |
| 英汉互译混合 | 汉译英与英译汉混合 | 双向提取 | 分题型判分 | P1 |
| 看英文写音标 | 英文词形 → 音标 | 音标产出 | 多读音与符号规则复杂 | P2 |
| 跟读评分 | 发音示范 → 学生录音 | 发音 | 独立语音评测 | P2 |

### 9.4 各题型交互规格

**汉译英：**

- 显示当前要考的核心中文释义和词性，多义词需明确词义序号或教材语境。
- 输入英文完整单词/短语，Enter 提交。
- 错误后显示正确拼写、字母差异、音标和播放。
- 用户写出该词的另一词义时，不应被误算为本词义正确。

**英译汉：**

- 显示英文、词性和可选例句；不显示中文选项。
- 默认支持一个核心释义输入框，多词义题展示需要回答的释义数量。
- 审核答案库包含核心释义、可接受近义表达和不应接受的过泛答案。
- 未命中答案库时标记“待确认”，展示参考释义；AI 可给建议但不能静默改分。
- 英译汉反映词义回忆，不计入英文拼写掌握。

**听音写词：**

- 进入题目后不自动反复播放；首次播放受浏览器策略限制时显示明确播放按钮。
- 提供重听，P1 可设置 0.75×/1× 语速；播放不显示英文词形。
- 音频失败时可重试或切换为汉译英，并标记该题未有效检测听音能力。
- 同音词需结合词性/中文提示，避免仅凭声音产生无解题目。

**看音标写英文：**

- 显示音标和词性，可选择英/美音标体系。
- 多读音、同音异形词必须配合释义或语境，否则不作为有效题。
- 音标缺失或异常时禁止出题，回退到其他题型。

**单词读写：**

1. 显示词形、释义、音标并播放。
2. 学生可点击“我已会读”或进行跟读录音（录音回放可先于评分）。
3. 切换到拼写步骤，隐藏词形，仅保留中文或发音提示。
4. 完成拼写后汇总“阅读完成 / 拼写结果 / 提示使用”。
5. 未完成发音评测前，不显示“发音标准分”。

### 9.5 英文判分规则

| 规则 | 默认处理 | 示例 |
|---|---|---|
| 首尾空格 | 去除 | `␣apple␣` → `apple` |
| 连续空格 | 合并 | `ice␣␣cream` → `ice cream` |
| 英文字母大小写 | 默认忽略 | `Apple` 与 `apple` 均可 |
| 中文/弯撇号 | 归一化 | `don’t` → `don't` |
| 连字符 | 默认严格比较 | `ice-cream` 不自动等于 `ice cream` |
| 英美拼写 | 仅审核为可接受答案时通过 | `color` / `colour` 需配置 |
| 多答案 | 任一审核答案通过 | 以词库配置为准 |
| 词形变化 | 未要求时不接受 | 目标 `go`，答 `went` 不通过 |
| 空答案 | 不允许提交 | 可选择跳过并单独记录 |
| 提示后答对 | 单独标记 | 不计入无提示首答正确 |
| 同题重试 | 首答结果保留 | 防止刷高首答率 |

### 9.6 中文释义判分规则

1. 中文首尾空格和常见全半角标点可归一化，但不能随意删除改变词义的文字。
2. 以词条审核的核心释义与可接受表达为准。
3. 多词义题必须明确需要几个释义，不能用一个词义覆盖全部要求。
4. 未命中答案库进入“待确认”，不直接计入正确或错误的历史掌握。
5. AI 同义判断只返回建议与理由，由用户确认后才写入本次结果；默认不自动修改词库。
6. 词义回忆与英文拼写分别统计。

### 9.7 提示、掌握与复习

| 状态 | 进入条件 |
|---|---|
| 未学习 | 没有学习或作答记录 |
| 学习中 | 已看过词卡或参与过练习 |
| 待复习 | 曾答错、提示后答对，或到达复习时间 |
| 本轮通过 | 当前题型无提示首答正确 |
| 已掌握（分技能） | 跨不同日期多次无提示正确，并通过后续抽测 |

- 拼写、听写、认词、发音分别保存状态。
- 单次答对只能叫“本轮通过”。
- P1 可采用 1/3/7/15 天等可解释间隔；答错缩短，连续独立答对拉长。
- 复习优先高风险错词，并限制每日任务量。
- 后续评估 FSRS 等算法时，必须能与规则方案做效果对比。

## 10. 信息架构与核心流程

### 10.1 新 SPA 一级导航

```text
学习首页 | 单词库 | 分类默写 | 错词复习 | 学习记录
```

二级/管理入口：

```text
词库导入 | 打印默写单 | 设置与数据
旧知识卡：通过“知识卡”外链返回旧系统首页 `/`
```

### 10.2 学习主流程

```text
选择词库 → 选择分类 → 选择题型 → 设置题量/顺序/提示
  → 作答 → 即时反馈 → 结果 → 只练错词 → 到期复习
```

### 10.3 PDF 导入流程

```text
导入中心 → 上传 PDF → 解析设置 → 异步解析
  → 异常校对 → 重复冲突处理 → 导入报告 → 发布词库
```

### 10.4 异常流程

- 无匹配词：禁止开始并提供清空筛选。
- 音频失败：重试或切换题型，不卡死。
- PDF 解析失败：显示失败页码/原因，可重试或改用 CSV。
- 刷新/关闭：恢复未完成会话。
- 重复提交：同题只记录一次。
- 词库更新：历史会话仍使用题目快照。
- 数据恢复：先预览、校验和备份，禁止默认覆盖现有数据。

## 11. 全功能 UI 设计规格

### 11.1 设计方向与记忆点

**方向：极致极简的学习工具。** 大面积暖白纸面、深蓝唯一主行动色、清晰排版和精确间距，不做渐变堆砌、通用三卡落地页或幼稚化游戏界面。

### 11.6 S02 词库选择

- 顶部标签：内置词库 / 我的词库。
- 词库行显示名称、适用学段、教材版本、词条数、版本、来源与更新日期。
- 默认选中当前词库；切换词库不删除历史学习数据。
- 主操作：“浏览单词”“开始默写”；次操作：“查看来源”。
- 自定义词库有草稿/已发布状态；草稿不能用于正式练习。
- 空态提供“导入词库”；来源不明或许可缺失时显示警告。

### 11.7 S03 单词列表

**布局：**

- 顶部：搜索框、当前词库、开始默写。
- 左侧筛选（桌面）：教材、年级、册别、单元、主题、词性、难度、学习状态。
- 右侧列表：英文、词性、核心释义、音标、发音、所属单元、学习状态。
- 批量选择后出现底部操作条：“已选 N 词”“加入练习”“清除”。

**交互与状态：**

- 搜索支持英文和中文，300ms 左右防抖；结果显示关键词。
- 多选分类用复选框；互斥教材版本用单选。
- 筛选条件写入 URL，刷新后保留。
- 分页或虚拟列表，不一次渲染 3000 条。
- 无结果时展示当前筛选和“一键清空”。
- 手机端筛选进入全屏抽屉，列表改卡片，批量条不遮挡底部导航。

### 11.8 S04 单词详情/学习卡

- 头部：英文词形、词性、英美音标、播放。
- 多词义使用标签切换，明确当前词义与练习对象。
- 中部：核心释义、例句与翻译、常见搭配。
- 分类：单元、主题、自定义来源。
- 学习记录：分别显示认词、拼写、听写状态，不给单一总分。
- 操作：“听音”“跟读/读写”“开始本词默写”“加入本轮”。
- AI 例句/助记（P1）默认折叠并标注 AI 辅助，可反馈内容错误。
- 音频加载、失败、无音标、多读音和 AI 生成失败均有独立状态。

### 11.9 S05 导入中心

- 顶部主按钮“新建导入”，旁提供“下载 CSV 模板”。
- 列表字段：文件名、类型、词库、状态、成功/警告/失败、创建时间、操作。
- 状态包括：待上传、解析中、待校对、待处理冲突、待发布、已完成、失败。
- 操作随状态变化：继续校对、处理冲突、查看报告、重试。
- 失败可查看具体原因；不允许用“成功”掩盖部分失败。
- 手机端以状态卡片展示，筛选按状态和时间。

### 11.10 S06 新建导入

采用四步向导，步骤条始终可见：

1. **选择类型**：CSV/JSON/PDF；显示各自支持范围。
2. **上传文件**：拖拽或选择；显示文件名、大小、页数/行数。
3. **导入配置**：目标词库、教材分类、字段映射、PDF 页面范围。
4. **确认开始**：解析说明、人工校对提示、预计异步处理。

**校验与反馈：**

- 非支持格式、超大文件、密码 PDF 就地报错。
- PDF 明确提示“解析结果需校对后发布”。
- 扫描型 PDF 若 OCR 尚未启用，提示当前不支持并建议文本 PDF/CSV。
- 上传有进度、取消和失败重试；重复文件不自动覆盖。

### 11.11 S07 PDF 解析进度

- 显示当前阶段：文件检查、文本提取、版面分析、字段识别、校验。
- 进度以真实页数/任务状态计算，不用虚假百分比。
- 可离开页面，后台继续；返回后恢复状态。
- 取消需确认，并说明已产生草稿如何处理。
- 失败显示阶段、页码、可读原因和重试入口。
- 解析完成自动进入校对，不直接进入正式词库。

### 11.12 S08 PDF 解析校对

**桌面采用左右对照，而非单一大表格：**

- 左侧：原 PDF 页预览、页码、当前条目原文定位。
- 右侧：候选词条表格，字段为单词、词性、释义、音标、单元、置信度、状态。
- 顶部：全部/低置信度/缺字段/疑似错行/已确认筛选。
- 编辑：点击行打开右侧编辑面板，保留原始文本。
- 批量：确认高置信度、标记异常、分配分类；批量操作可撤销。
- 底部：已确认/待处理数量，主按钮“下一步：处理重复”。

**手机端：** 原文预览与字段编辑切换为两个标签，不强塞双栏。

**状态：** 解析空结果、原文定位失败、字段校验错误、未保存离开、自动保存失败都必须可见。

### 11.13 S09 重复与冲突处理

- 每组冲突展示“现有词条 vs 导入词条”的字段差异。
- 冲突类型：完全重复、同词不同词性、同词不同词义、字段冲突。
- 操作：保留现有、保留导入、人工合并、作为新词义添加。
- 完全重复可批量保留现有；字段冲突禁止一键全覆盖。
- 顶部显示剩余冲突数；未处理完不可发布。
- 所有决定写入导入报告，支持返回修改。

### 11.14 S10 导入报告与发布

- 汇总：读取、有效、警告、拒绝、重复、最终新增/更新数量。
- 错误明细可下载，包含行号/页码、字段和原因。
- 发布前显示目标词库和版本说明输入框。
- 主按钮“发布词库”；发布成功提供“浏览单词”“开始默写”。
- 部分成功必须明确显示，不用绿色成功横幅掩盖失败。
- 发布中禁止重复点击；失败保留草稿与校对结果。

### 11.15 S11 默写配置

**桌面双栏：左侧配置，右侧实时摘要；手机单列，底部固定摘要。**

| 配置区 | 控件与规则 |
|---|---|
| 练习范围 | 当前词库、教材单元、主题、错词/自定义选择 |
| 练习模式 | 卡片式单选，显示各题型检测能力；不可多选除非选择“混合” |
| 题量 | 10/20/30 分段单选；不足时显示实际数量 |
| 顺序 | 随机/词表顺序；复习模式可按风险优先 |
| 提示 | 首字母、分级提示开关；说明提示会影响统计 |
| 发音 | 英/美偏好、语速（P1）；音频不可用时提前提示 |
| 反馈 | 即时反馈默认；集中反馈 P1 |
| 摘要 | 词数、题型、预计范围、可用音频/音标数量 |

无有效词、所需音标/音频全部缺失时禁用开始并给出修复入口。

**题型子界面：**

| 子模式 | 题干区 | 作答区 | 辅助操作 | 反馈 |

- 手机软键盘弹出时题干和按钮可见，底部操作不遮挡输入。

### 11.17 S13 练习结果

- 顶部：本次完成题数、无提示首答正确、提示后答对、待确认、跳过。
- 分技能标签：拼写/听写/认词，避免把不同题型合并。
- 主按钮：“只练本次错词”；次按钮：“再练一组”“查看学习卡”。
- 错词列表：我的答案、标准答案、差异、词义、发音、错误类型。
- 英译汉待确认项单独分组，不计入确定错误。
- 无错时仍提供到期复习说明，不显示“永久掌握”。
- 分享/打印为次操作，不用庆祝动画遮挡结果。

### 11.18 S14 错词本

- 顶部指标：当前待复习、顽固错词、本轮已通过；不展示无法解释的风险分。
- 筛选：教材/单元/主题、题型、错误次数、最近时间、状态。
- 列表：词形、词性、释义、最近错误答案、错误次数、下次复习、状态。
- 详情抽屉：历史作答时间线、各题型结果、音标/例句。
- 批量操作：选择错词 → 听写/汉译英/混合重练。
- 重练通过不删除历史，只更新状态。
- 空态区分“从未有错词”和“筛选无结果”。

### 11.19 S15 复习计划

- 今日到期任务置顶，显示建议完成量和预计词数。
- 新词与复习词比例可调，但默认优先清理到期复习。
- 每词显示下次复习时间和原因，如“昨天听写答错”。
- 可调整每日上限；调整不删除到期记录。
- P2 算法模式必须提供“为什么现在复习”的简释。
- 无到期任务时推荐单元学习，不制造虚假逾期。

### 11.20 S16 学习历史

- 会话列表：时间、词库/范围、题型、完成度、首答结果、状态。
- 筛选：日期、题型、完成/未完成。
- 详情：使用当时题目快照，不受词库后续更新影响。
- 未完成会话可继续；已完成会话可查看结果或再练。
- 不提供隐蔽清除历史；数据删除属于数据管理且需明确确认。

### 11.21 S17 学习统计

- 指标：无提示首答正确率、提示依赖率、错词重练通过率、待复习数。
- 图表按拼写、听写、认词分标签，不能拼成一个总分。
- 趋势图同时提供数据表；无数据不画假趋势。
- 薄弱分类只基于足够作答样本，并显示样本量。
- 不用学习时长和打卡天数替代学习效果。
- 手机端图表横向不溢出，可切换列表视图。

### 11.22 S18 打印默写单

- 范围：单元、主题、当前筛选、错词、历史会话。
- 版式：汉译英、英译汉、听写（家长念词表）、混合。
- 设置：A4、每页词数、是否显示词性/首字母、是否附答案页。
- 预览：学生卷与答案卷分开，页码和词库版本可见。
- 打印前检查空范围；答案页默认独立分页。
- 听写单答案页包含标准词形和释义，方便家长念中文或英文。

### 11.23 S19 设置

| 旧功能 | 返回知识卡系统 |

### 11.24 S20 数据管理

- 显示数据库/学习数据状态、最近备份时间、词库版本。
- 导出备份包含 schema 版本和词库版本，不包含 API Key。
- 恢复流程：选择文件 → 校验 → 预览影响 → 自动备份当前数据 → 用户确认后执行。
- 不默认覆盖；冲突策略明确。
- 删除词库、历史或缓存属于独立危险操作，必须列出影响并由用户确认，不提供一键全清。

### 11.29 响应式与可访问性验收

- 检查 375、768、1440px，不允许横向溢出或主按钮被遮挡。
- 全部功能可键盘操作，`:focus-visible` 清晰。
- 点击目标 ≥44×44px；正文对比度 ≥4.5:1。
- 正误、置信度和状态同时用文字/图标，不只用颜色。
- 所有动效在 `prefers-reduced-motion` 下关闭或降级。
- 音标、长英文、长中文释义、多词义和长文件名不撑破布局。
- PDF 校对双栏在移动端有替代交互。
- 关键控件使用稳定 `data-testid`，如 `practice-answer-input`、`practice-submit`、`wrong-word-retry`。

## 12. 数据模型草案

| 实体 | 关键字段 | 说明 |
|---|---|---|
| `Word` | `id, lemma, difficulty, level, source, version` | 词形主数据，不直接承担全部词义 |
| `WordSense` | `id, word_id, pos, meaning_zh, sense_order, example, example_zh` | 词性/词义学习单元 |
| `WordAnswer` | `sense_id, answer_type, answer, locale, is_primary` | 英文、中文等可接受答案 |
| `Pronunciation` | `word_id, accent, phonetic, audio_url, status, source` | 英美音标与音频 |
| `Category` | `id, type, name, parent_id, sort_order` | 教材/单元/主题等分类 |
| `Wordbook` | `id, name, stage, version, source, license, status` | 词库、来源、许可与版本 |
| `ImportBatch` | `id, file_name, file_type, status, target_wordbook, schema_version, created_at` | 导入批次 |
| `ImportItem` | `id, batch_id, page_no, raw_text, parsed_data, confidence, review_status, error` | 原文与校对草稿 |
| `ImportConflict` | `id, batch_id, existing_id, incoming_data, resolution` | 重复与字段冲突决策 |
| `PracticeSession` | `id, mode, filters_snapshot, size, order, status, started_at, finished_at` | 一次练习 |
| `PracticeItem` | `id, session_id, sense_id, sequence, prompt_snapshot, skill` | 会话题目快照 |
| `PracticeAnswer` | `id, item_id, answer_raw, answer_normalized, result, review_status, hint_used, duration_ms, client_attempt_id` | 作答与待确认状态 |
| `SkillProgress` | `sense_id, skill, status, correct_count, wrong_count, hint_count, streak, last_practiced_at, due_at` | 按词义和技能分进度 |

`skill` 至少包括 `meaning_recall`、`spelling`、`listening_spelling`、`phonetic_spelling`、`pronunciation`。首版只真实计算已实现技能，不预填虚假分数。

### 13.1 新接口通用约束

- 当前题响应不下发标准答案，判分在服务端完成。
- `client_attempt_id` 防止重试造成重复作答。
- PDF 解析等长任务使用异步状态和真实进度。
- 导入条目默认草稿，未校对/未发布不能用于正式练习。
- 所有错误使用统一结构，不返回密钥或内部异常。
- 单词列表必须分页；文件上传限制类型与大小。
- 旧 `/api/generate` 保持兼容，新契约只约束 `/api/v1`。

## 15. 指标体系

| 指标 | 定义 | 用途 |
|---|---|---|
| 无提示首答正确率 | 无提示且首次提交正确的题数 / 实际有效作答题数 | 独立产出能力 |
| 拼写掌握进度 | 拼写题型跨日期复核状态 | 衡量会写，不与认词混算 |
| 听写首答正确率 | 听音写词有效题的首答结果 | 衡量音形对应 |
| 词义回忆通过率 | 英译汉已确认结果 | 衡量认词，排除待确认题 |
| 提示依赖率 | 使用提示题数 / 实际作答题数 | 识别答案线索依赖 |
| 错词重练通过率 | 错词重练无提示首答通过数 / 重练题数 | 判断订正效果 |
| 会话完成率 | 完成会话 / 已开始会话 | 定位题量和交互中断 |
| PDF 校对修正率 | 被人工修改的候选条目 / 候选总条目 | 判断解析质量与是否可扩大自动化 |
| PDF 页级失败率 | 解析失败页 / 总页数 | 定位版式和 OCR 问题 |

不把学习时长、点击次数、打卡天数单独当作学习效果，不设无依据提分承诺。

## 16. 验收标准与测试重点

### 16.1 架构验收

1. 旧知识卡首页、生成、预览和导出全部回归通过。
2. 新 Vue 前端独立构建，使用 `/api/v1`，不依赖 Jinja 变量。
3. `/app/*` 刷新正常，且不拦截任何旧路由。
4. 新模块下线后旧系统仍可访问。
5. 新数据库和旧 `output/cache` 数据互不污染。

### 16.2 内容与 PDF 验收

1. 内置词库有来源、许可、版本和稳定 ID。
2. CSV/JSON 错误行有报告，冲突不默认覆盖。
3. 文本 PDF 候选词保留页码与原文，低置信度可见。
4. 双栏、表格、跨行、音标、撇号、连字符有专项测试样本。
5. 扫描 PDF 未达质量门槛前只能人工校对，不能自动发布。
6. 未发布草稿不出现在学生练习中。
7. 词库更新后历史会话快照和进度不串词。

### 16.3 学习与默写验收

1. 汉译英、听音写词主链路完整，其他题型按阶段验收。
2. 英译汉待确认不直接污染正确率。
3. 大小写、空格、撇号、连字符、多答案符合规则。
4. 多词义题明确考哪个词义，进度不混算。
5. 提示后答对不计入无提示首答正确。
6. 同题重复提交不重复计数。
7. 音频失败可重试或切换题型。
8. 刷新、浏览器重启、服务重启后按设计恢复。
9. 错词重练有独立结果，历史不被覆盖。
10. 认词、拼写、听写和发音报告分别统计。

### 16.4 UI 验收

1. S01～S21 已实现范围均有加载、空、错误和禁用状态。
2. 375/768/1440px 无横向溢出，移动键盘不遮挡作答。
3. 全部功能可键盘操作，焦点清晰，对比度达标。
4. PDF 校对移动端可完成，不仅桌面可用。
5. UI 自动化覆盖导入、配置、作答、判分、错词重练和旧功能回归。

## 18. 四角色评审结论

### 18.1 资深产品经理（PM）

- 核心差异化是“多来源分类词库 + 分技能默写闭环”，不是再做一个 AI 词卡展示页。
- PDF 是内容生产效率功能，不能抢占学生学习主链路的 MVP 资源；文本 PDF 与 OCR 必须分期。
- 英译汉、音标、读写可组成完整学习版，但数据模型必须从现在就区分词义和技能。
- AI 的价值应落在降低录入成本、增强语境和解释错误，而不是替代规则与审核。

### 18.2 资深 UI/交互设计师（UI）

- 新 SPA 与旧知识卡视觉可保持品牌关联，但新模块需要独立组件和状态体系。
- 所有题型共用一个作答壳，只替换题干、输入和反馈，避免每个题型形成不同交互习惯。
- PDF 校对的核心是“原文对照 + 异常筛选 + 批量确认”，不是普通上传进度条。
- 掌握反馈必须分技能；移动端键盘、音标长文本、表格卡片化和打印分页是专项验收点。
- 设计记忆点放在拼写差异和清晰反馈，不做通用渐变卡片和过度游戏化。

### 18.3 资深测试工程师（QA）

- 高风险区域：PDF 错行/错配、多词义串进度、中文待确认、音标字符、音频失败、会话恢复和新旧路由冲突。
- 导入需要固定样本集和页级质量指标，不能只凭几个看起来正确的词判断可用。
- 英译汉必须测试同义、过泛、错误、多词义和待确认，不允许 AI 静默改分。
- 契约测试保护新前端，旧路由回归保护原系统；数据库迁移必须测试保留数据。
- UI 自动化覆盖主链路和异常状态，稳定选择器在开发时同步落地。

### 18.4 资深开发工程师（Dev）

- 推荐同仓库 Flask Blueprint + Vue3/Vite/Pinia，新 API 与 SPA 同域生产部署，旧业务不改。
- 需要一次性修改入口注册新模块，但不修改旧路由函数、模板和缓存逻辑。
- 新数据采用 SQLite + 迁移，词义、发音和技能进度分表，避免未来重构。
- PDF 采用异步任务和可恢复批次；文本提取、OCR、AI 结构化分层，避免一个大函数包办。
- 判分服务保持纯规则、可单测；AI 服务独立适配，失败不影响核心练习。
